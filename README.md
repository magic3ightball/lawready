# lawready

글로벌 개인정보 문서 생성·버전관리 서비스의 기획 문서를 관리하는 저장소입니다.

## 문서 구성

| 구분 | 파일 | 용도 |
|---|---|---|
| 서비스 소개 | [`docs/서비스_소개서.md`](docs/서비스_소개서.md) | LawReady 제품이 해결하는 문제, 대상 고객, 사용자 흐름, 제공 범위와 차별점을 이해하기 위한 문서 |
| 기능정의 | `docs/기능정의서.docx` | MVP 28개 기능과 완료조건, 공통 발행 차단 규칙 정의 |
| 기능정의 부록 | `docs/기능정의서_기술검토_부록.docx` | 도메인·상태·비기능·오픈소스·기존 68개 ID 매핑 보관 |
| 기획 대화 기록 | [`docs/서비스_기획_대화_기록_2026-08-25.md`](docs/서비스_기획_대화_기록_2026-08-25.md) | 서비스 범위 결정 배경과 확장 아이디어를 확인하기 위한 발화자별 원문 기록. 확정 범위 판단에는 사용하지 않음 |

제품을 처음 이해할 때는 `서비스_소개서.md`를 먼저 확인합니다. 기능 구현 범위를 판단할 때는 `기능정의서.docx`를 기준 문서로 사용합니다. 기술검토 부록은 구현 참고자료이며, 부록의 내용만으로 MVP 범위를 확대하지 않습니다.

## 변경 관리 원칙

1. 문서를 수정하기 전에 변경 목적과 영향을 `CHANGELOG.md`에 기록합니다.
2. 서비스 범위가 바뀌면 소개서와 기능정의서의 표현이 일치하는지 함께 확인합니다.
3. 기능 추가·삭제 시 기능 ID, 완료조건, 공통 검증 규칙, 기존 ID 매핑을 함께 갱신합니다.
4. 법률 콘텐츠 변경은 국가·기준일·검수자를 남기고 별도 법률 검수를 거칩니다.
5. 서비스 소개서는 Markdown을 기준으로 관리하고, DOCX 기능 문서 변경은 커밋 메시지에 변경 범위를 구체적으로 적습니다.

## 권장 커밋 메시지

- `docs(intro): 대상 고객과 제공 범위 수정`
- `docs(spec): PUB-03 발행 차단 조건 보완`
- `docs(appendix): 오픈소스 검토 결과 갱신`
